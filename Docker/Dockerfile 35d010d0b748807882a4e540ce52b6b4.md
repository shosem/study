# Dockerfile

〜イメージを作るファイル。Dockerfileをbuildしてイメージが作られるよ

## よく使う命令

| 命令 | 目的 | 使用例 |
| --- | --- | --- |
| `FROM` | ベースイメージを指定 | `FROM ruby:3.1` |
| `RUN` | パッケージやライブラリを追加 | `RUN apt-get install -y nodejs` |
| `COPY` | ファイルをコンテナへコピー | `COPY . /app` |
| `WORKDIR` | 作業ディレクトリの指定 | `WORKDIR /app` |
| `ARG` | ビルド時のみ使える変数の定義 | `ARG APP_ENV=development` |
| `ENV` | 実行時の環境変数を定義 | `ENV APP_ENV $APP_ENV` |
| `EXPOSE` | 公開するポートの宣言 | `EXPOSE 3000` |

### FROM

環境構築の土台。OSやランタイムが最初から用意されたイメージをベースに使う

> 説明：Ruby3.1がインストールされた公式のDockerイメージをベースとして利用
> 

```docker
FROM ruby:3.1
```

### RUN

ベースイメージに含まれないパッケージやツールを追加でインストール

> 説明：`apt-get update`でインストールできるリストを更新
　　　`install`で`nodejs`をインストール
> 

```docker
RUN apt-get update && apt-get install -y nodejs
```

### COPY / ADD

ホスト側のアプリケーションコードや設定ファイルをイメージに取り込む

> 説明：カレントディレクトリのすべてのファイルを、
　　　コンテナ内の`/app`ディレクトリにコピー
> 

```docker
COPY . /app
```

※ コンテナにはディレクトリやファイルなども独自のディレクトリ空間として作られる。

### WORKDIR

以降の命令実行時の作業フォルダを指定。

> 説明：/appディレクトリを作業場所として指定。以降のRUNやCOPYはこの場所を基準に。
> 

```docker
WORKDIR /app
```

### **ARG / ENV**

ビルド時 / コンテナ実行時の環境変数を設定

> ARG：ビルド時（ビルド中）のみ有効な変数を設定。上書き可能
ENV：コンテナ起動後も使える環境変数。上書き不可。
> 

```docker
ARG APP_ENV=development  # developmentを格納
ENV APP_ENV $APP_ENV     # 上で定義したAPP_ENVを環境変数として設定
```

※ ARGは書き換え可能なので、developmentとproductionを切り替えるのに使える。
　ENVは書き換え不可なので、ENV PORT=3000 など固定のものを設定する。
　上記例はAPP_ENVを書き換え可能にしてるので、build時にproductionを指定すればいい。

### EXPOSE

コンテナが外部に後悔するポート番号を宣言。

> アプリが内部で使用するポートを明示
> 

```docker
EXPOSE 3000
```
