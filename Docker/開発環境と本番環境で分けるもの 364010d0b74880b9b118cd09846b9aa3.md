# 開発環境と本番環境で分けるもの

## そもそも

開発：デバッグ、ホットリロードできる

本番：速度や軽量さ、セキュリティ

## 1. インストールするパッケージ・ツール

開発：エディタやログ確認、バージョン管理するツール
　　　（開発時はvimエディタでファイルを編集したり、など）

本番：上記は不要、DBに接続するためのライブラリや、キャッシュの削除
　　　（本番では編集やテストはしないので不要、むしろリスク）

```docker
# Dockerfile.dev（開発環境）
RUN apt-get update && apt-get install -y \
    vim \           # エディタ（コンテナ内でファイル編集）
    less \          # ログ確認用
    git \           # バージョン管理
    curl \          # API テスト
    postgresql-client  # DB 接続確認用
    
    
    
# Dockerfile（本番環境）
RUN apt-get update && apt-get install -y \
    libpq-dev \     # PostgreSQL 接続に必要な最小限のライブラリ
    && rm -rf /var/lib/apt/lists/*  # キャッシュ削除でサイズ削減
```

### gemもそう

```docker
# Gemfile
group :development, :test do
  gem 'byebug'           # デバッガ
  gem 'pry-rails'        # 対話的デバッグ
  gem 'rspec-rails'      # テストフレームワーク
  gem 'factory_bot_rails'  # テストデータ作成
end

group :development do
  gem 'web-console'      # ブラウザでデバッグ
  gem 'listen'           # ファイル変更検知
end
```

```docker
# Dockerfile.dev（開発環境）
RUN bundle install  # すべての Gem をインストール

# Dockerfile（本番環境）
RUN bundle install --without development test  # 開発・テスト用を除外
```

## 2. コードの配置方法

開発：コードを編集すると、即コンテナ内のものにも反映

本番：COPYされる（イメージで完結される）

```docker
# compose.yml（開発環境）
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.dev
    volumes:
      - .:/app  # ホストのコードをコンテナにマウント
    command: bundle exec rails server -b 0.0.0.0
    
    
# Dockerfile（本番環境）
COPY . .  # コードをイメージに焼き込む
RUN bundle exec rails assets:precompile  # アセットもビルド時に処理
```

## 3. サーバー設定

開発：railsの開発サーバー（puma。エラーメッセージなど表示される）

```docker
# Dockerfile.dev
CMD ["bundle", "exec", "rails", "server", "-b", "0.0.0.0"]
```

本番：本番用サーバー（複数プロセス・スレッドを処理）
